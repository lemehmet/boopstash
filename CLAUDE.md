- Read `docs/adr/` before changing anything about privacy, storage, the editor, distribution or formatting. A change that contradicts an ADR needs a new ADR.
- Privacy is a hard constraint: no network access beyond the user's iCloud, no background pasteboard reads, no new entitlement without an ADR, AI is on-device only. The one exception is ADR 0014: a language model endpoint the user configures themselves may be asked to draft a script, off by default, with the request made only by the sandboxed model helper process (never by the app, which keeps no network entitlement) and carrying, of the user's text, only the instruction and the sample and examples the workbench shows (ADR 0014 lists the rest of a request: our fixed prompt, the model name, the settings, the user's extra fields and their key).
- Every new or changed piece of pure logic lands in `BoopstashCore` with Swift Testing tests. Only thin `Live*` adapters in `App/` import AppKit, CloudKit, Vision or JavaScriptCore.
- The app is sandboxed in every build; never add code that only works unsandboxed.
- Generated `.xcodeproj` / `.xcworkspace` are never committed. `mise exec -- tuist generate`. Swift packages go in `Project.swift`'s `packages:` (Xcode-native), never `Tuist/Package.swift` (ADR 0006).
- Minimum deployment target is macOS 26 / iOS 26. No availability checks for older OS versions.
- Plan and milestones: `docs/plan/milestones.md`.
- This repository is public. Never commit secrets or signing material (certificates, `.p8`/`.p12`, provisioning profiles, API keys, deploy keys, `.env` files), absolute local paths, or personal data such as real notes, clipboard contents or screenshots. Secrets reach CI only through GitHub Actions secrets; test fixtures are synthetic.
- PR review: at most 3 fuko review rounds per PR. Comments raised in round 3 become follow-up GitHub issues (not more fix commits), and the PR gets the `review-capped` label so rebases do not start a fourth round.
